<objective>
Remove the build transport from the CLI and reshape `appo ship` from a 4-step
(create → build → poll → publish) pipeline to a 2-step (create → publish-intent)
one. Builds are issued by Appo staff server-side; the v1 `POST /api/v1/apps/{app}/builds`
route now returns 405 (legacy 404) for a user PAT, so any surviving trigger is an
opaque runtime failure. This plan deletes `ops.triggerBuild`, the `pollBuild` loop,
`realSleep`, the build/poll ledger steps, and the `--timeout` plumbing; it reshapes
`ship` to reuse `ops.publishApp` verbatim as the intent signal; and it reshapes the
ship test surface to assert request-absence of `/builds`.

Purpose: Satisfy SC-1 (ship = create + publish-intent, no build, no poll) and SC-2
(no CLI code path issues `POST .../builds`).
Output: Reshaped `src/ops.mjs` (triggerBuild gone, createApp metadata params dropped),
reshaped `src/cli.mjs` (`case 'ship'`, EXIT map, USAGE), reshaped
`test/integration/ship.test.mjs`, deleted `test/unit/ship.test.mjs`.
</objective>
